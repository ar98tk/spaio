# Spaio Email Deliverability Checklist

Spaio sends account verification, invoice, and subscription reminder emails through Laravel mail and the database queue.

## Runtime Settings

Production `.env` should use:

```dotenv
APP_NAME=Spaio
MAIL_MAILER=smtp
MAIL_SCHEME=smtps
MAIL_HOST=mail.your-domain.com
MAIL_PORT=465
MAIL_FROM_ADDRESS="spaio@your-domain.com"
MAIL_FROM_NAME="Spaio"
MAIL_VERIFY_PEER=true
QUEUE_CONNECTION=database
```

The local development server may need `MAIL_VERIFY_PEER=false` only when the SMTP server certificate is invalid. Production should use a valid certificate and keep peer verification enabled.

## Required DNS Records

Configure these records wherever the sending domain DNS is managed:

- SPF: allow the SMTP provider to send email for the domain.
- DKIM: publish the public DKIM key generated by the mail provider.
- DMARC: start with monitoring, then move to quarantine or reject after testing.
- MX: keep valid inbound mail records if the same domain receives replies.

Exact SPF and DKIM values must come from the mail hosting provider.

## Queue Worker

Queued emails will not leave the app unless a worker is running:

```bash
php artisan queue:work --tries=3 --backoff=60
```

Use Supervisor, systemd, Laravel Forge, or another process manager in production.

## Scheduled Reminders

Spaio queues subscription reminders three days before a trial or billing period ends:

```bash
php artisan subscriptions:send-renewal-reminders
```

The scheduler is registered to run daily at 09:00. Production needs one cron entry:

```bash
* * * * * cd /path/to/spaio && php artisan schedule:run >> /dev/null 2>&1
```

## Failure Handling

Email notifications are queued with three attempts and backoff delays of 60, 300, and 900 seconds. Failed jobs are stored in the `failed_jobs` table for review and retry.
